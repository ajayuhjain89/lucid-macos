## Configuration and workflow

- App and website are one Git repository: `https://github.com/ajayuhjain89/lucid-macos`.
  `website/` resolves to the parent Git root; there is no second website repository.
- Start branch: `logic`, at `acc1b1a1bb4935a027269135e69aa10a8b6d9d8d`.
  Existing source changes, new services, regression suites and audit reports were preserved.
- Permanent flow: `logic` / `design` / `docs` → `develop` → `main`. Never back-merge
  integration into category branches. Engineering and developer qualification work remains on `logic`; user documentation is
  prepared in an isolated checkout of the established `docs` branch. Both integrate forward.
- Live protection on both `develop` and `main` requires PRs, the Build (macOS, Apple Silicon)
  and Validate PR direction checks, and forbids force-pushes. Admin enforcement is enabled.
- Semver patch convention gives 1.0.8; monotonically increasing CFBundleVersion gives 9.
  Release tag must be annotated `v1.0.8`, on the final qualified `main` commit.
- Vercel Git deployments: `main` is Production; observed `develop` and `logic` deployments
  are Preview. `website/vercel.json` disables docs/design deployments. Production origin is
  `https://website-phi-umber-70.vercel.app`, also configured in Info.plist's SUFeedURL.
- `build.sh` assembles/signs/packages arm64; signing is **ad hoc**, including Sparkle helpers.
  `--release` creates the versioned DMG with overwrite protection. It does not notarize.

## CI toolchain correction

The category push exposed an older compiler error on the macOS-14 CI runner: a
main-actor prompt method used as a default argument was evaluated outside its actor.
The prompt and shared restorer defaults now resolve inside their main-actor methods,
preserving the injected test paths and native behavior. Required checks are rerun on
this correction; the original failed run is retained in GitHub history. A subsequent run
compiled and signed the app, then exposed an older Swift Testing optional-chain macro
expansion error. Unwrapping the snapshot in its own required assertion preserves both
snapshot-presence and tab-content checks while compiling on that toolchain.

## Unresolved publication gates

1. **Developer ID signing / notarization:** `security find-identity -v -p codesigning`
   reports **0 valid identities**. No signing identity or notarization configuration is
   defined by the repository. The checked `Lucid` notary profile is absent. Website
   download/signing copy explicitly reserves Developer ID signing and Apple notarization
   for stable. Ad-hoc signature verification cannot satisfy this promise. Need an installed
   Developer ID Application identity with its private key and an authorized notary credential
   profile on the release machine (or a configured signing runner); never place keys in Git.
2. **Supported-OS runtime qualification:** deployment minimum is 14.0 and Sparkle's minimum
   is 12.0, but those are metadata, not runtime tests. No macOS 14, 15 or 26 runtime environment
   is available locally. Existing CI is a macOS-14 build/test gate; its new candidate result
   must pass, and native OS-matrix evidence remains needed. The unsubstantiated website
   “Tested on macOS 14/15” claim was removed from the candidate.
3. **Actual Sparkle upgrade:** live download/install/relaunch from 1.0.7, interruption and
   rollback remain unperformed. Need a final signed/notarized candidate and a controlled
   update feed using the existing EdDSA public key, then verify retained documents/settings
   and interruption behavior. The production feed must stay on 1.0.7 until this passes.
4. **Final distribution validation:** a local ad-hoc development package can be prepared,
   but no stable Developer ID/notarized package exists. After integration and qualification,
   rebuild from the final release commit; verify nested signatures, notarization/staple,
   quarantined first launch and App Translocation, mounted installation, Info.plist version,
   arm64/minimum OS, SHA-256/length, and EdDSA against Info.plist's key.

Not performed: physical power-loss/sleep-wake, real cross-volume moves, full denied-read/TCC
matrix, long resource-pressure runs, exhaustive native export visual matrix. Recovery uses a
250 ms debounce and asynchronous preferences persistence; zero lost last keystrokes is not
claimed. No Intel compatibility claim is made.
