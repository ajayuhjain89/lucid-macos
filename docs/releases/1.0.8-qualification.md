## OS-matrix evidence and native resolutions

The category push previously resolved compiler and Swift Testing macro expansions on macOS 14 runners, followed by returning concrete values to WebKit async JavaScript overlays to prevent an older Swift async bridge crash. Following that fix, macOS 14 passes all build, signing, Node suites, 124 Swift tests, and branch-flow policy checks cleanly.

Subsequent matrix runs surfaced two environment-specific timing and event-ordering issues:
1. **Reading-position preservation during resize (macOS 15):** A macOS 15 run recorded actual reading line ~99.89 instead of the saved ~120 after resizing from width 850 to 650. Investigation showed an application event-ordering defect: during window resize, WebKit reflowed content and fired a native `scroll` event. In `bridge.js`, the scroll handler updated `lastUserScrollTimestamp`, treating the layout-induced scroll as user interaction. When `geometryFrame` ran, `lastUserScrollTimestamp === update.userScroll` evaluated to false, aborting `scrollToSourceLine(update.anchor)`. Fixed in `bridge.js` by explicitly tracking `isResize` in `pendingGeometry` so layout reflow cannot cancel reading anchor restoration across window resizes, and updated `LayoutInteractionTests.swift` to boundedly flush frames for WebContent layout stabilization before asserting.
2. **Image refresh after tab switch (macOS 26):** In `StableReleaseRegressionTests.swift`, `sameMarkdownTabSwitchReloadsRelativeImages` previously asserted image width after an arbitrary fixed 500 ms sleep. On loaded runners, SwiftUI tab-state propagation and image decode exceeded 500 ms. Replaced the arbitrary sleep with bounded polling (up to 4.0 s, 20 ms intervals) for `naturalWidth == 2`, making the test deterministic without fixed delays.
